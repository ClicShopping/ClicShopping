6.1. RÈGLES DE SYNTAXE ORDER BY (CRITIQUE - ÉVITE LES ERREURS DE RÉFÉRENCE DE COLONNE) :
Lorsque vous employez des fonctions d'agrégation (YEAR, QUARTER, MONTH, etc.) dans un GROUP BY, vous DEVEZ suivre ces règles pour l'ORDER BY :
RÈGLE 1 : employez la MÊME expression de fonction dans ORDER BY que dans GROUP BY
✅ CORRECT : SELECT YEAR(date) AS year_value ... GROUP BY YEAR(date) ORDER BY YEAR(date)
✅ CORRECT : SELECT QUARTER(date) AS quarter ... GROUP BY QUARTER(date) ORDER BY QUARTER(date)
✅ CORRECT : SELECT MONTH(date) AS month_num ... GROUP BY MONTH(date) ORDER BY MONTH(date)
❌ FAUX : SELECT YEAR(date) AS year_value ... GROUP BY YEAR(date) ORDER BY year
❌ FAUX : SELECT QUARTER(date) AS quarter ... GROUP BY QUARTER(date) ORDER BY quarter
❌ FAUX : SELECT MONTH(date) AS month_num ... GROUP BY MONTH(date) ORDER BY month
RÈGLE 2 : OU employez les numéros de position de colonne (1, 2, 3, etc.)
✅ CORRECT : SELECT YEAR(date), SUM(value) ... GROUP BY YEAR(date) ORDER BY 1
✅ CORRECT : SELECT QUARTER(date), COUNT(*) ... GROUP BY QUARTER(date) ORDER BY 1
RÈGLE 3 : OU employez le nom d'alias si vous en avez créé un
✅ CORRECT : SELECT YEAR(date) AS year_value ... GROUP BY year_value ORDER BY year_value
✅ CORRECT : SELECT QUARTER(date) AS quarter_num ... GROUP BY quarter_num ORDER BY quarter_num
RÈGLE 4 : ne référencez JAMAIS un nom de colonne qui n'existe pas comme alias
❌ FAUX : SELECT YEAR(date) ... ORDER BY year (la colonne 'year' n'existe pas !)
❌ FAUX : SELECT QUARTER(date) ... ORDER BY quarter (la colonne 'quarter' n'existe pas !)
EXEMPLES DE MOTIFS CORRECTS :

RAPPEL : la clause ORDER BY doit référencer soit :
1. L'expression de fonction exacte du SELECT/GROUP BY
2. Un numéro de position de colonne (1, 2, 3...)
3. Un alias que vous avez explicitement créé dans le SELECT
Elle NE PEUT PAS référencer un nom de colonne qui n'existe ni dans la table ni comme alias !

13. COMPARAISONS TEMPORELLES : lorsque vous comparez des mesures entre périodes (par exemple "mai vs février", "cette année vs la même période l'an dernier") :
- Employez CASE WHEN avec SUM() pour créer des colonnes distinctes, une par fenêtre, étiquetées current_ / previous_
- Exemple : SUM(CASE WHEN date >= '2026-05-01' AND date < '2026-06-01' THEN value ELSE 0 END) AS may_value
- FENÊTRES APPARIÉES (OBLIGATOIRE) : les deux fenêtres DOIVENT couvrir le MÊME nombre de jours. Construisez la précédente en décalant la courante en arrière avec INTERVAL 1 YEAR (ou INTERVAL 1 MONTH). Comparer une période courante partielle à une période précédente entière rend toute variation fausse, et fausse dans le sens qui rassure.
- Chaque CASE écrit LES DEUX bornes de sa propre fenêtre, en intervalle de dates explicite
- Renvoyez les résultats sur une seule ligne, avec plusieurs colonnes
- LA VARIATION DÉPEND DU TYPE DE MESURE : un MONTANT, un COMPTE ou une DURÉE varient en pourcentage — (courant - précédent) / précédent * 100. Un TAUX (un pourcentage, une part, un taux de conversion) varie en POINTS DE POURCENTAGE — taux_courant - taux_précédent. Un taux passant de 70 % à 72,73 % gagne +2,73 points de pourcentage, jamais "+3,9 %" : diviser un taux par un autre est une erreur de catégorie, et elle est indétectable une fois imprimée dans un tableau.
14. EXPRESSIONS TEMPORELLES DYNAMIQUES : un FILTRE de période est TOUJOURS un intervalle explicite sur la colonne de date brute - jamais YEAR(), MONTH() ou QUARTER() dans un WHERE. Prenez les bornes dans le PLAN D'ANALYSE, sinon dans le bloc CURRENT DATE CONTEXT. Un intervalle construit depuis le premier jour d'une période franchit le changement d'année par construction.
- "30 derniers jours" → WHERE {{domain_date_column}} >= CURDATE() - INTERVAL 30 DAY
- "Cette semaine" → WHERE {{domain_date_column}} >= CURDATE() - INTERVAL WEEKDAY(CURDATE()) DAY AND {{domain_date_column}} < CURDATE() + INTERVAL 1 DAY
- "Le mois dernier" → WHERE {{domain_date_column}} >= DATE_FORMAT(CURDATE() - INTERVAL 1 MONTH, '%Y-%m-01') AND {{domain_date_column}} < DATE_FORMAT(CURDATE(), '%Y-%m-01')
- "Ce mois-ci" → WHERE {{domain_date_column}} >= DATE_FORMAT(CURDATE(), '%Y-%m-01') AND {{domain_date_column}} < CURDATE() + INTERVAL 1 DAY
- "Le trimestre dernier" → WHERE {{domain_date_column}} >= MAKEDATE(YEAR(CURDATE()), 1) + INTERVAL (QUARTER(CURDATE()) - 2) * 3 MONTH AND {{domain_date_column}} < MAKEDATE(YEAR(CURDATE()), 1) + INTERVAL (QUARTER(CURDATE()) - 1) * 3 MONTH (posée en janvier 2026, c'est du 1er octobre au 31 décembre 2025)
- "Cette année" → WHERE {{domain_date_column}} >= MAKEDATE(YEAR(CURDATE()), 1) AND {{domain_date_column}} < CURDATE() + INTERVAL 1 DAY
YEAR(), MONTH() et QUARTER() ne servent qu'au GROUP BY d'une ventilation par période (REQUÊTES TEMPORELLES MULTI-PÉRIODES).

text_sql_rules_grain = GRAIN - VALEURS AU NIVEAU EN-TÊTE AU-DESSUS D'UNE JOINTURE DE LIGNES
Une jointure d'une table d'en-tête vers l'une de ses tables de lignes, ou à travers une liaison plusieurs-à-plusieurs, transforme un en-tête en UNE LIGNE PAR LIGNE. Toute valeur du niveau en-tête présente sur ces lignes - un montant, une date - est RÉPÉTÉE une fois par ligne.
{{domain_grain_tables}}
Le piège n'est pas un GROUP BY manquant, c'est une SUM sur une valeur répétée. À l'intérieur d'un GROUP BY sur l'identifiant de l'en-tête qui joint aussi une table de lignes, une SUM sur une valeur d'en-tête la multiplie par le nombre de lignes. Prenez une valeur répétée du niveau en-tête avec MAX - une valeur par en-tête - ou gardez la jointure de lignes hors de l'agrégat et restreignez la population avec EXISTS.
{{domain_grain_examples}}
Cela ne vaut que pour les valeurs au niveau EN-TÊTE. Une mesure au niveau ligne - une quantité, un nombre de lignes, le montant d'une ligne - s'agrège sur la table de lignes comme d'habitude et ne doit PAS être pré-agrégée au grain de l'en-tête.
PART D'UNE COMPOSANTE DANS UN TOTAL : ne faites JAMAIS un INNER JOIN sur la composante que vous mesurez : un en-tête sans ligne de cette composante disparaît alors aussi du DÉNOMINATEUR, et le ratio ressort surestimé. Agrégez les deux côtés en une seule passe, avec des sommes conditionnelles sur une jointure unique.
{{domain_grain_classes}}
