# Introduction
help_intro_title = Qu'est-ce que la Business Intelligence RAG (RAG BI) ?
help_intro_text = La RAG BI est votre assistant intelligent pour analyser vos données métier en langage courant. Au lieu d'écrire des requêtes de base de données, vous posez simplement des questions comme :
help_intro_example_1 = Combien de produits avons-nous ?
help_intro_example_2 = Quelles sont nos ventes ce mois-ci ?
help_intro_example_3 = Montre-moi les 10 produits les plus vendus
help_intro_description = Le système comprend votre question, génère la requête de base de données appropriée, récupère les données et les présente dans un format clair et lisible. Il peut aussi chercher dans vos documents, combiner les deux, et atteindre le web lorsque cela est configuré.

# Technical Information
help_technical_title = Informations techniques

help_embeddings_title = À propos des embeddings et de la recherche sémantique
help_embeddings_text = Le « support des embeddings » signifie que le modèle peut être utilisé pour la recherche sémantique. Un modèle d'embedding dédié convertit vos documents en vecteurs recherchables, puis le modèle de chat les utilise pour trouver l'information pertinente.
help_embeddings_with = <strong>Avec support des embeddings :</strong> les fournisseurs cloud (OpenAI, Anthropic, Mistral, Gemini) gèrent l'analytique et la recherche sémantique.
help_embeddings_without = <strong>Sans support des embeddings :</strong> la plupart des modèles locaux (LM Studio, Ollama) sont réservés à l'analytique.

help_notes_title = Notes importantes
help_notes_1 = Chaque modèle doit être configuré dans les paramètres Modèles IA (clé API, fenêtre de contexte, tarifs).
help_notes_2 = Les modèles locaux nécessitent LM Studio ou Ollama en cours d'exécution sur votre serveur.
help_notes_3 = Les temps de réponse varient selon la complexité de la question, le modèle choisi et la charge du serveur.
help_notes_4 = La justesse de l'analyse dépend du modèle : un modèle de raisonnement à grand contexte est le plus fiable.

# LLM Configuration (local models)
help_llmconfig_title = Configuration des LLM locaux (LM Studio / Ollama)
help_llmconfig_intro = Les modèles locaux doivent pouvoir contenir le prompt analytique de ClicShopping, qui inclut le schéma de la base et peut atteindre environ 25 000 tokens. Configurez le modèle en conséquence sur votre serveur local.
help_llmconfig_context = <strong>Fenêtre de contexte :</strong> chargez le modèle avec un contexte d'au moins 32 000 tokens. Un modèle limité à 16k (par exemple Phi-4) ne peut pas répondre aux requêtes analytiques — le prompt seul dépasse sa fenêtre et la réponse revient vide.
help_llmconfig_reasoning = <strong>Modèles à raisonnement</strong> (avec une étape de réflexion interne, comme Qwen3) : ils consacrent une partie de leur budget de sortie à réfléchir avant de répondre. Définissez une limite de sortie suffisante (LM Studio utilise jusqu'à 8000 tokens) sinon la réponse finale est tronquée ou vide. Les modèles non-raisonnants évitent ce problème et sont plus rapides.
help_llmconfig_speed = <strong>Temps de réponse :</strong> un modèle local peut prendre plusieurs minutes par réponse analytique selon votre matériel ; les modèles cloud répondent en quelques secondes.
help_llmconfig_reliability = Les modèles de raisonnement à grand contexte donnent l'analyse la plus fiable.
help_llmconfig_pricing = Les tarifs d'utilisation des modèles peuvent varier. Veuillez les mettre à jour.
